# Windows Clash 流量账本设计

## 目标

把现有 `clash-traffic-monitor` 改造成可长期运行的 Windows 托盘程序。程序持续读取 Clash Verge Rev 内置 Mihomo 的连接状态，永久记录每个可观测连接由什么软件发起、访问什么目标、经过什么策略组和实际节点，以及上传和下载字节数。

交付物是单个 Windows EXE。用户登录后自动启动；点击托盘图标打开本地统计页面。无需 Python、Docker或单独数据库服务。

## 已确认口径

- 采集 Mihomo 接管的全部连接。
- `DIRECT` 与代理流量严格分开；机场消耗口径只统计代理流量。
- 永久保留每条被采集器观测到的连接记录。
- 永久保留分钟明细，并维护小时、日、周、月四级汇总。
- 支持按软件、软件路径、域名、目标 IP、路由类型、策略链和实际节点筛选。
- 所有数据只保存在本机。

## 技术边界

Mihomo 的 `/connections` 是活动连接快照，不是系统级抓包。采集器每秒读取一次，因此能够准确累计所有被至少一次快照观测到的连接；在两次采样之间创建并关闭的极短连接可能无法记录。程序不会宣称统计未被 Mihomo 接管的流量，也不会把本地 `DIRECT` 流量算作机场流量。

## 方案选择

保留上游的 Go 单二进制、SQLite 和嵌入式 Web UI 架构。与从零编写 C# 程序相比，这能复用已经验证过的连接增量、计数器重置处理、SQLite 查询和图表；与直接安装现成版本相比，又能补齐进程维度、永久保存和 Clash Verge 命名管道。

Windows 连接优先使用 `npipe://verge-mihomo`，由 `microsoft/go-winio` 接入 `\\.\pipe\verge-mihomo`。普通 HTTP Controller 继续保留，便于测试和兼容其他 Mihomo 客户端。

托盘使用纯 Go 的 Windows 托盘实现。主菜单提供“打开流量账本”“暂停/继续采集”“开机自动启动”“打开数据目录”“退出”。界面仍由本机 `127.0.0.1` HTTP 服务提供，托盘点击后调用默认浏览器打开。

## 数据模型

### 连接账本 `connection_sessions`

每个 Mihomo 连接 ID 对应一行，并通过 UPSERT 更新：

- `connection_id`
- `started_at`、`first_seen_at`、`last_seen_at`、`ended_at`
- `network`、`connection_type`
- `source_ip`、`source_port`
- `destination_ip`、`destination_port`、`host`
- `process`、`process_path`
- `route_type`：`PROXY`、`DIRECT` 或 `REJECT`
- `outbound`：实际出口节点；直连时为 `DIRECT`
- `chains_json`：完整策略链
- `rule`、`rule_payload`
- `upload`、`download`

连接首次出现时插入；后续快照覆盖累计字节数和最后观察时间；从活动集合消失时写入结束时间。Mihomo 重启或计数器回退时，旧会话统一结束，新快照重新建立基线，避免重复累计。

### 分钟事实表 `traffic_aggregated`

沿用现有分钟增量表，增加 `process_path`、`route_type`、`rule`、`rule_payload`。每次采样只写相对上次快照的正增量，因此总量不会随轮询重复计算。

### 分层汇总 `traffic_rollups`

统一表保存 `hour`、`day`、`week`、`month` 四种粒度，维度包括：

- 软件与软件路径
- 路由类型
- 实际节点与完整策略链
- 域名与目标 IP
- 匹配规则
- 上传、下载、连接数

汇总使用确定性 UPSERT，可从分钟事实表完整重建。小时桶结束后生成小时汇总；日、周、月在边界结束后生成，同时启动时补齐缺失桶。周以周一 00:00 为起点，所有时间按 Windows 本地时区展示并以带偏移时间写入。

原始连接、分钟事实和四级汇总均不自动删除。界面提供数据库大小、最早记录时间、最后备份时间；不提供一键清空按钮，避免误删永久账本。

## 采集与持久化流程

1. 启动后连接命名管道；Clash Verge 尚未启动时进入等待状态并指数退避，最高 30 秒。
2. 每秒读取 `/connections`。
3. 以连接 ID 对比上次快照，计算上传和下载增量。
4. 在一个 SQLite 事务中更新连接会话、分钟事实和运行状态。
5. 每分钟结束后落盘该分钟桶；程序退出时同步刷新。
6. 后台补建小时、日、周、月汇总。
7. Clash/Mihomo 重启、配置切换、管道断开后自动重连，不退出托盘程序。

SQLite 使用 WAL、`busy_timeout` 和单写入协程。写入失败时保留待写批次并重试；磁盘不可写或空间不足时，托盘状态变红并显示明确错误，不静默丢弃。

## 用户界面

首页默认显示“代理流量”，可切换“全部 / 代理 / DIRECT / REJECT”。顶部卡片显示上传、下载、总量、连接数、采集状态和数据库大小。

主分析维度新增“软件”，并保留域名、目标 IP、节点。时间范围提供本小时、今天、本周、本月、自定义；粒度可选小时、日、周、月。点击软件后显示该软件使用过的节点、域名和连接明细。连接明细展示进程路径、开始/结束时间、完整策略链和规则。

页面只监听 `127.0.0.1`。Mihomo 密钥不返回前端、不写日志。

## Windows 安装与生命周期

- 默认程序目录：`%LOCALAPPDATA%\ClashTrafficMonitor\app`
- 数据目录：`%LOCALAPPDATA%\ClashTrafficMonitor\data`
- 日志目录：`%LOCALAPPDATA%\ClashTrafficMonitor\logs`
- 登录自启：当前用户注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
- 单实例：第二次启动只打开已有页面，不再启动采集器。
- 正常退出：先停止采集、结束活动会话、刷新分钟桶、关闭 HTTP 和数据库，再移除托盘图标。

安装脚本只复制发布文件并登记当前用户自启，不需要管理员权限。卸载默认保留数据库，只有明确选择“同时删除数据”才移除账本。

## 测试与验收

自动化测试覆盖：

- 首次连接、持续连接、关闭连接和连接 ID 复用。
- 上传/下载计数器回退和 Mihomo 重启。
- `DIRECT`、代理和 `REJECT` 分类。
- 进程、路径、节点、域名和规则写入。
- 小时、日、周、月边界及跨月、跨年场景。
- 重启补建汇总且不重复计数。
- 命名管道 HTTP 响应、分块编码和断线重连。
- 永久保留配置下不执行流量删除。
- API 按软件、节点、路由类型和时间筛选。
- Windows 单实例、自启注册和优雅退出。

最终验收包括：完整 `go test ./...`、Windows EXE 构建、连接本机 `verge-mihomo` 管道、后台运行观察、页面查询真实进程/节点数据、重启后数据连续性、托盘菜单和登录自启验证。

## 非目标

- 不抓取 Mihomo 之外的系统流量。
- 不修改机场订阅、代理规则或节点选择。
- 不上传遥测或同步到云端。
- 不承诺恢复安装前的历史流量。
- 首版不加入自动切换节点功能的新行为；保留上游已有功能，但默认不启用。
